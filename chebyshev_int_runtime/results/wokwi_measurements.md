# Wokwi Measurements

This document records the latency and accuracy measurements obtained by simulating the integer-only firmware on the two target boards (Arduino Mega 2560 and ESP32-C3) using the Wokwi simulator. Each configuration corresponds to a separate firmware in [`../mcu/`](../mcu/), built against a sanity-check set of 40 test vectors generated by the Python reference and embedded in the corresponding `test_vectors*.h` header.

All numbers below are simulator-measured (board-side micros() counters, reported via UART). Physical-hardware validation is identified as future work in the main [`README.md`](../README.md).

---

## Binary intrusion detection — single-layer KAN (10 edges)

Model: Chebyshev single-layer, 10 input features → 1 output, degree 8.
Test set: 12 000 TON_IoT flows (binary normal / attack), seed = 42, stratified 80/20.

### Reference performance (Python / float)

| Metric          | Value  |
|-----------------|--------|
| F1              | 0.969  |
| ROC-AUC         | 0.987  |
| Memory (LUT)    | 10 KB  |

### On-device latency (Wokwi)

| Board                | Float baseline | Mixed-int | **Integer-only** | Speedup (full)   |
|----------------------|----------------|-----------|------------------|------------------|
| Arduino Mega 2560    | 2851 µs        | 680 µs    | **357 µs**       | **8.0×**         |
| ESP32-C3-SuperMini   | 1665 µs        | 207 µs    | **38 µs**        | **44×**          |

Mega/ESP32-C3 latency ratio under the float baseline: **1.7×** (artefact of software FPU emulation, equal in absolute cost across the two platforms).
Mega/ESP32-C3 latency ratio under integer-only inference: **9.4×**, matching the underlying clock ratio (160/16 MHz = 10×).

### On-device accuracy

Integer-only firmware on the 40-vector sanity-check set: **97.5 %** (39/40). Per-vector logits match the Python reference within ±1–2 units (rounding); argmax is identical on every vector tested.

Firmware: [`../mcu/main_kan_wokwi_fullint.cpp`](../mcu/main_kan_wokwi_fullint.cpp)
LUT header: [`../mcu/kan_ids_layer_int.h`](../mcu/kan_ids_layer_int.h)
Test vectors: [`../mcu/test_vectors_q16.h`](../mcu/test_vectors_q16.h)

## Multiclass intrusion detection — multi-layer KAN (320 edges)

Model: two-layer Chebyshev KAN, 10 → 16 → 10, tabulated `tanh` activation between layers, degree 8.

### Reference performance

| Metric                  | Value         |
|-------------------------|---------------|
| Macro-F1 (float)        | 0.918         |
| Macro-F1 (integer LUT)  | 0.916         |
| Memory (LUT, total)     | 320 KB        |

The 0.002 macro-F1 drop between float and integer corresponds to the quantization noise of the staged LUT compilation (`int16` per-edge, `int32` accumulation, tabulated `tanh` with 2048 samples mapped to scale `S2 = 10000`). Argmax matches the float forward in **99.7 %** of the 12 000 test samples.

### Full-test-set evaluation

Beyond the 80/20 stratified split (12 000 test samples) used during training and verification, the multi-layer model was evaluated on the complete TON_IoT dataset (211 043 flows), with the model and preprocessing trained on the same 80/20 split and never retrained.

| Subset                     | Accuracy | Macro-F1 | Weighted-F1 |
|----------------------------|----------|----------|-------------|
| 80/20 test split (12 k)    | 0.9623   | 0.9118   | —           |
| Full dataset (211 k)       | 0.9644   | **0.9177** | 0.9663    |

Per-class F1 on the full dataset is strong on most classes (0.94–1.00) and concentrates almost all of the gap with gradient-boosted baselines on the **MITM** class (F1 = 0.49, recall 0.88, precision 0.34), which is the smallest class in TON_IoT (1 043 of 211 043 samples = 0.5 %). Excluding MITM, the multi-layer macro-F1 reaches **0.9652**.

### On-device performance (Wokwi, ESP32-C3)

| Metric                              | Value           |
|-------------------------------------|-----------------|
| Latency per inference               | **691 µs**      |
| On-device accuracy (40-vector set)  | **95 %** (38/40)|

## Summary

The integer-only LUT compilation eliminates the floating-point multiplication from the inference inner loop while preserving accuracy to within a fraction of a per-cent. On boards with hardware FPU (ESP32-C3) the speedup over a float baseline is one to two orders of magnitude; on boards without FPU (Arduino Mega 2560) it is approximately 8× and removes the cost of software-emulated floating-point that previously dominated the inference time.

The Python ↔ C correspondence has been verified vector-by-vector for every firmware, on the same 40-vector sanity-check set generated from the test split; the macro-F1 of the underlying model on the complete test set is reported above for reference but is by definition unchanged by the firmware (the firmware is a faithful integer realization of the same forward).

---

## Notes on simulation vs. hardware

All numbers above are obtained in Wokwi simulation. The simulator models the target architectures faithfully enough to give meaningful relative comparisons (float vs. integer, Mega vs. ESP32-C3), but absolute latencies on physical silicon may differ by a small factor due to memory access patterns, cache behaviour, and peripheral interaction not fully modelled by the simulator. Migration to physical hardware is the natural next step and is identified as such in the parent [`README.md`](../README.md).
